# CERBERUS Cyber independent evaluation candidate

Research maturity is TRL 2–3. The measured runtime at `e740091cee1a74b34c46e2e9f71e4dbc1c82d1e7` combines the #22 broker and #28 historical evidence. This package adds a fixed scenario runner, a store identity check and measured observations. The 90-row sample and 22-case contract output are in [results](../../../results/authority_integration_v1/). Authority decisions use synthetic requests and ephemeral keys.

## Implemented boundary

An untrusted scripted proposer supplies an envelope. Guardian checks policy and fabricated signed evidence and approval proofs. The trusted controller registers the signed grant. The broker accepts a fixed action, target and scope, verifies the exact envelope through the gateway, checks live registry status under its process-local lock, consumes token and execution claims in one SQLite transaction, rechecks expiration and writes one controller-owned marker. The evaluator observes the marker and canary separately, checks the returned decision, counts writes and verifies the local audit chain. The nine-case runner calls the broker directly. A separate Landlock demo runs the worker as a restricted OS process.

The broker now retains its verified SQLite store object. Each consumption still opens a fresh connection and checks database integrity under the transaction. The store samples device and inode during admission, verification and before commit. An observed replacement refuses the operation. Trusted directory ownership, stable path components and control of the host remain assumptions. Sampling cannot prove file identity throughout arbitrary concurrent rename cycles, prevent inode reuse, authenticate old snapshots or preserve the pin over restart. Audit hashes need an independent anchor to establish external authenticity.

## Comparable authorization mechanisms

OPA separates the policy decision from the application that enforces it. The comparable split here is Guardian and the broker. A policy decision alone provides no evidence that the intended resource changed. [OPA integration documentation](https://www.openpolicyagent.org/docs/integration)

OAuth token introspection defines an active-status query for resource servers. CERBERUS checks its process-local registry and binds authority to an envelope and a single durable consumption. This comparison concerns architecture only. There is no interoperability or comparative performance result. [RFC 7662](https://datatracker.ietf.org/doc/html/rfc7662)
